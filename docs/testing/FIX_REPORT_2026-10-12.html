Espressoulster audit fixes — 12 October 2026

  • Shared customer/admin requests now abort after 15 seconds and show a retry message.
  • Cart updates debounce and coalesce; checkout flushes pending saves and reports persistence errors. Unchanged refreshes no longer write the cart.
  • Quantity increases in menu, editor and cart enforce aggregate stock limits.
  • Order hydration now uses four queries per page instead of up to 101 for 50 orders.
  • Customer history uses an authorized, paginated endpoint covering all customer orders, with accurate totals and ordered items.
  • Admin history separates fulfilment status from payment status and displays recorded payment method, subtotal, discount, tax, fees and total. Staff can record cash, UPI or card. Legacy payment records retain their original method rather than guessing.
  • Admin displays zero inventory as out of stock. Order-filter responses cannot overwrite newer requests.
  • Item IDs are visible in the list and editor. Edit buttons have explicit type and accessible labels; no underlying modal defect was reproduced during source inspection.
  • Activity log labels describe what changed and the affected record.
  • Stale gateway tests replaced with current PhonePe configuration, webhook, checkout-host and completed-transaction checks. This does not enable real payments.

Validation

TypeScript check passed. Build passed. Pricing, subscriptions, payment security and request timeout test files passed. Final built Worker: 63/63 backend tests passed, including new collection-method/customer-history tests and existing concurrent duplicate-order and overselling tests.

Limits

Production load balancing, sustained mixed traffic, failover and real gateway settlement remain unverified. The prior 150-request local read test is not production capacity evidence. Timeout failures on writes may have an uncertain server outcome; order idempotency remains in place. The report does not claim every possible failure has been tested.
